\# Лабораторна робота №7

\## React: компонентний інтерфейс застосунку



\### Мета роботи

Ознайомитися з React, створити компонентний інтерфейс застосунку, організувати спільний стан, реалізувати форми, завантаження даних і маршрутизацію.



\### Посилання на проєкт

\- Репозиторій GitHub: https://github.com/024864-netizen/university-schedule

\- Опублікований застосунок: https://024864-netizen.github.io/university-schedule/



\### Використані технології

\- React

\- TypeScript

\- Vite

\- React Router

\- HTML і CSS

\- Git та GitHub



Додатково реалізовано компонент `RecordModal` для відображення деталей запису у модальному вікні.



\### Управління станом

У компоненті `App` зберігається спільний стан:

\- `records` — список записів;

\- `loading` — стан завантаження;

\- `error` — повідомлення про помилку;

\- `search` — рядок пошуку.



Стан розміщено в найближчому спільному батьківському компоненті, щоб передавати дані дочірнім компонентам через типізовані props.



\### Завантаження даних

Дані завантажуються з файлу `data.json` за допомогою `fetch` у хуку `useEffect`. Для скасування запиту під час очищення ефекту використовується `AbortController`.



Передбачено відображення стану завантаження, повідомлення про помилку та списку записів. Якщо записів немає, відображається відповідне повідомлення.



\### Форми та валідація

Форма додавання запису містить поля назви, опису та категорії. Поля контролюються станом React. Перед додаванням перевіряється, чи заповнені назва й опис. У разі помилки користувач бачить повідомлення.



\### Список і ключі

Для відображення записів використовується `map()`. Кожна картка отримує стабільний ключ `key={record.id}`. Це дозволяє React правильно ідентифікувати елементи списку під час оновлення й не використовувати індекс масиву як ключ.



\### Маршрутизація

За допомогою React Router реалізовано головну сторінку зі списком і сторінку деталей запису. Ідентифікатор запису передається в URL. На сторінці деталей є посилання для повернення до списку.



\### Перевірка

Під час розробки виконано команди:

\- `npm run lint`

\- `npm run typecheck`

\- `npm run build`



Усі три команди завершилися без помилок. Під час production-збірки виводилися попередження залежності `react-router`, які не завадили успішній збірці.
