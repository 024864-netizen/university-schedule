# Лабораторна робота № 8
## REST API на Node.js та Express

### Мета роботи
Розробити REST API для вебзастосунку University Schedule з використанням Node.js та Express.

### Використані технології
- Node.js
- Express
- JavaScript
- CORS
- dotenv
- Nodemon
- Thunder Client

### Структура проєкту
- `routes` — маршрути API.
- `controllers` — обробка запитів.
- `services` — бізнес-логіка.
- `repositories` — зберігання даних.
- `middleware` — логування та обробка помилок.
- `server.js` — налаштування та запуск сервера.

### Реалізовані маршрути

| Метод | Маршрут | Призначення |
|---|---|---|
| GET | `/api/v1/disciplines` | Отримання списку |
| GET | `/api/v1/disciplines/:id` | Отримання дисципліни |
| POST | `/api/v1/disciplines` | Створення |
| PUT | `/api/v1/disciplines/:id` | Оновлення |
| DELETE | `/api/v1/disciplines/:id` | Видалення |

### Пагінація
Реалізовано параметри `page` та `limit`.

Приклад:
`GET /api/v1/disciplines?page=1&limit=2`

### Валідація
Перевіряються код, назва, кількість кредитів, семестр та унікальність коду дисципліни.

Використовуються статуси:
- `400` — некоректний запит.
- `404` — запис не знайдено.
- `409` — конфлікт даних.
- `422` — помилка валідації.
- `500` — помилка сервера.

### Обробка помилок
Реалізовано middleware для логування запитів та централізованої обробки помилок. Відповіді повертаються у форматі JSON.

### Конфігурація
Параметри сервера зберігаються у `.env`. Файл `.env.example` містить приклад налаштувань. Файл `.env` виключений із Git.

### Перевірка
За допомогою Thunder Client перевірено:
- отримання списку дисциплін;
- пагінацію;
- отримання одного запису;
- створення дисципліни;
- валідацію некоректних даних;
- оновлення;
- видалення.

Колекція запитів збережена у `server/collections/University-Schedule-API.json`.

### Висновок
Під час лабораторної роботи створено REST API на Node.js та Express для керування дисциплінами. Реалізовано CRUD-операції, пагінацію, валідацію, логування та обробку помилок. Перевірено роботу API за допомогою Thunder Client.
